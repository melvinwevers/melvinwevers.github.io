Deterministic code, probabilistic meaning: on translating research back and forth with LLMs

Recently I had a conversation about how large language models are changing the way we do research, and one distinction kept coming back. Code is deterministic. Language, and the conceptual thinking we do in it, is probabilistic. Code runs. Language has to be interpreted. I have come to think this distinction is useful but slightly wrong, and the way in which it is wrong matters. In computational history we constantly move between these two registers. I write a script that counts words in digitized newspapers, classifies photographs or extracts fields from housing registration cards. Given the same input, it produces the same output. Then I look at the result and have to decide what it means. Is a spike in a word frequency a shift in public discourse, or a change in how a newspaper was digitized? The first step is mechanical.
